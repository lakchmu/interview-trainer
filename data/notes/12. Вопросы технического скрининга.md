Вопросы, которые вероятнее всего прозвучат на техническом скрининге, по темам типового списка для подготовки к интервью. У каждого два ответа: «Коротко» — то, что нужно сказать вслух за 20–30 секунд, и «Развёрнуто» — на случай уточняющих вопросов. В конце — прогноз по лайвкодингу.

> Как пользоваться: прочитай вопрос, ответь вслух сама и только потом сверь с «Коротко». «Развёрнуто» читай там, где ответ не сложился. Это типовые вопросы скрининга по этим темам, а не расшифровка реального собеседования. Разделов: 5.

## 1. JavaScript

### Какие типы данных есть в JavaScript?

**Коротко.** Семь примитивов — `string`, `number`, `bigint`, `boolean`, `undefined`, `null`, `symbol` — и объекты; массивы и функции тоже объекты. Примитивы хранятся и сравниваются по значению, объекты — по ссылке.

**Развёрнуто.**
- `typeof null` даёт `'object'` — историческая ошибка языка. Массив проверяют через `Array.isArray`.
- Примитив неизменяем: методы строки возвращают новую строку.
- `{} === {}` ложно: это два разных объекта, сравниваются ссылки.
- `number` — числа с плавающей точкой, отсюда `0.1 + 0.2 !== 0.3`.

### Чем отличаются var, let и const?

**Коротко.** `var` виден во всей функции, всплывает со значением `undefined` и допускает повторное объявление. `let` и `const` блочные, и до строки объявления к ним обращаться нельзя. `const` запрещает переприсваивание, но не изменение самого объекта.

**Развёрнуто.**
- Всплывают все три, но `let` и `const` до объявления лежат во «временной мёртвой зоне» — обращение даёт ошибку.
- `var` в цикле с `setTimeout` печатает одно и то же число, `let` — разные: у `let` на каждую итерацию своя переменная.
- В `const`-массив можно добавлять элементы: запрещено только присвоить переменной другое значение.
- По умолчанию пишут `const`, `let` — когда значение меняется.

### Чем == отличается от ===?

**Коротко.** `===` сравнивает без приведения типов, `==` сначала приводит операнды к одному типу. В коде используют `===`; единственное принятое исключение — `x == null`, которое ловит сразу `null` и `undefined`.

**Развёрнуто.**
- При `==` строка и булево значение приводятся к числу, объект — к примитиву: `'5' == 5`, `[] == false` — истина.
- `null == undefined` истинно, и больше ничему они не равны.
- `NaN` не равен ничему, даже себе; проверяют `Number.isNaN`.
- Ложных значений восемь: `false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN`. Всё остальное истинно, включая `[]`, `{}` и `'0'`.

### Чем null отличается от undefined, а ?? от ||?

**Коротко.** `undefined` — значение не задано: переменная без значения, отсутствующее свойство, функция без `return`. `null` — «пусто», поставленное намеренно. `??` подставляет запасное значение только для `null` и `undefined`, а `||` — для любого ложного, поэтому съедает `0`, `''` и `false`.

**Развёрнуто.**
- `count || 10` при `count = 0` даст 10, `count ?? 10` — 0. Для значений по умолчанию нужен `??`.
- `user?.address?.city` — опциональная цепочка: вернёт `undefined`, если слева `null` или `undefined`, вместо ошибки.
- В JSON поля со значением `undefined` пропадают, `null` сохраняется.

### Что такое замыкание?

**Коротко.** Функция запоминает переменные той области, где была создана, и имеет к ним доступ, даже когда внешняя функция уже завершилась.

**Развёрнуто.**

```js
function counter() {
  let n = 0
  return () => ++n
}
const next = counter()
next() // 1
next() // 2 — переменная n жива, хотя counter завершилась
```

- Применения: приватное состояние, `debounce`, `once`, мемоизация, любые обработчики событий.
- Цена: пока жива функция, живы и её внешние переменные — так возникают утечки памяти.
- Классическая ловушка — `var` в цикле: все колбэки видят одну переменную.

### Как определяется this?

**Коротко.** По способу вызова, а не по месту объявления. Вызов как метода — объект перед точкой; обычный вызов — `undefined` в строгом режиме; с `new` — новый объект; через `call`, `apply`, `bind` — то, что передали. У стрелочной функции своего `this` нет, она берёт его из внешней области.

**Развёрнуто.**
- Приоритет: `new` → `bind`/`call`/`apply` → вызов метода → по умолчанию.
- Потеря контекста: `const f = obj.method; f()` или `setTimeout(obj.method, 0)` — метод оторван от объекта.
- Лечится обёрткой `() => obj.method()` или `obj.method.bind(obj)`.
- Стрелочная функция в роли метода объекта получит внешний `this`, а не объект.

### Чем стрелочная функция отличается от обычной?

**Коротко.** У стрелочной нет своих `this`, `arguments` и `prototype`; её нельзя вызвать с `new`, а `call` и `bind` не меняют её `this`. Она удобна для колбэков и не подходит как метод объекта или конструктор.

**Развёрнуто.**
- Объявление `function f() {}` всплывает целиком; стрелочная — это выражение, доступна только после присваивания.
- Вместо `arguments` используют остаточные параметры `(...args)`.
- Тело без фигурных скобок возвращает значение неявно; объект при этом берут в круглые скобки: `() => ({ a: 1 })`.

### Что делают call, apply и bind?

**Коротко.** Все три задают `this`. `call` и `apply` вызывают функцию сразу: первый принимает аргументы через запятую, второй — массивом. `bind` ничего не вызывает, а возвращает новую функцию с закреплённым `this` и, при желании, первыми аргументами.

**Развёрнуто.**

```js
fn.call(ctx, 1, 2)
fn.apply(ctx, [1, 2])
const bound = fn.bind(ctx, 1)
bound(2) // fn вызвана с this = ctx и аргументами 1, 2
```

- Привязанную функцию нельзя перепривязать повторным `bind`.
- Свой `bind` в одну строку: `(...args) => fn.apply(ctx, [...first, ...args])`.

### Как работает event loop?

**Коротко.** JavaScript выполняется в одном потоке: есть стек вызовов и очереди задач. Когда стек опустел, выполняются все микрозадачи — колбэки промисов и код после `await`, затем одна макрозадача — таймер, событие, ответ сети; после этого браузер может отрисовать кадр, и цикл повторяется.

**Развёрнуто.**

```js
console.log(1)
setTimeout(() => console.log(2), 0)
Promise.resolve().then(() => console.log(3))
console.log(4)
// 1 4 3 2
```

- Микрозадачи выполняются до конца, включая добавленные по ходу; бесконечная цепочка микрозадач заблокирует отрисовку.
- `setTimeout(fn, 0)` — не «сразу», а «не раньше следующей макрозадачи».
- Код после `await` — это микрозадача.

### Что такое промис и какие у него методы?

**Коротко.** Промис — объект, представляющий будущий результат. У него три состояния: ожидание, выполнен, отклонён; сменить состояние можно один раз. `then`, `catch` и `finally` возвращают новый промис, поэтому их выстраивают в цепочку.

**Развёрнуто.**

| Метод | Когда завершается |
| --- | --- |
| `Promise.all` | когда выполнены все; первая ошибка отклоняет всё |
| `Promise.allSettled` | когда завершились все, с любым исходом |
| `Promise.race` | по первому завершившемуся, с любым исходом |
| `Promise.any` | по первому успешному |

- `catch` в конце цепочки ловит ошибку из любого звена выше; после него цепочка продолжается как успешная.
- Колбэки `then` всегда выполняются асинхронно, даже если промис уже выполнен.

### Как работает async/await и как обрабатывать ошибки?

**Коротко.** `async`-функция всегда возвращает промис. `await` приостанавливает её до результата, не блокируя поток. Ошибки ловят через `try/catch`, а независимые запросы запускают параллельно через `Promise.all`.

**Развёрнуто.**

```js
// по очереди — медленно
const a = await getA()
const b = await getB()
// параллельно
const [a, b] = await Promise.all([getA(), getB()])
```

- `fetch` отклоняется только при сбое сети; ответы 404 и 500 проверяют через `res.ok`.
- `await` внутри `forEach` ничего не ждёт; нужен `for...of` или `Promise.all(arr.map(…))`.
- Забытый `await` — промис вместо значения и необработанная ошибка.

### Что такое прототип и что делает new?

**Коротко.** У каждого объекта есть скрытая ссылка на прототип. Свойство ищется сначала в самом объекте, потом по цепочке прототипов до `null`. `new` создаёт пустой объект, связывает его с `Fn.prototype`, вызывает функцию с `this`, равным этому объекту, и возвращает его.

**Пример.**

```js
function User(name) {
  this.name = name // при вызове с new здесь this — новый объект
}
User.prototype.hi = function () {
  return "Привет, " + this.name
}

const anya = new User("Аня")
anya.hi() // "Привет, Аня" — метод найден в прототипе
Object.hasOwn(anya, "hi") // false: своего hi у объекта нет
Object.getPrototypeOf(anya) === User.prototype // true

// то же самое, что делает new, по шагам:
const obj = Object.create(User.prototype) // объект с нужным прототипом
User.call(obj, "Аня") // вызов функции с this = obj
```

**Развёрнуто.**
- `__proto__` — ссылка объекта на его прототип; `prototype` — свойство функции-конструктора, которое станет прототипом её экземпляров.
- Методы массивов лежат в `Array.prototype`, поэтому есть у всех массивов.
- `Object.create(proto)` создаёт объект с заданным прототипом без конструктора.
- `obj instanceof Fn` проверяет, есть ли `Fn.prototype` в цепочке.

### Что такое классы в JavaScript?

**Коротко.** Класс — запись поверх прототипов: методы лежат в `prototype`, `extends` связывает прототипы, `super` обращается к родителю. От функции-конструктора класс отличается тем, что его нельзя вызвать без `new`, и у него есть приватные поля `#x` и `static`.

**Пример.**

```js
class Animal {
  #sound // приватное поле: снаружи недоступно
  constructor(name, sound) {
    this.name = name
    this.#sound = sound
  }
  speak() { return `${this.name}: ${this.#sound}` }
}
class Dog extends Animal {
  constructor(name) {
    super(name, "гав") // сначала родитель, только потом this
  }
  speak() { return super.speak() + "!" } // поверх родительского
}

const rex = new Dog("Рекс")
rex.speak() // "Рекс: гав!"
typeof Dog // "function": класс — это функция
Object.hasOwn(rex, "speak") // false: метод лежит в Dog.prototype
Dog() // TypeError: без new класс вызвать нельзя
```

**Развёрнуто.**
- В конструкторе наследника до вызова `super()` нельзя обращаться к `this`.
- Инкапсуляция — приватные поля и замыкания; наследование — цепочка прототипов; полиморфизм — переопределение методов.
- Глубокие иерархии связывают классы жёстко; чаще выбирают композицию.

### Что такое деструктуризация, spread и rest?

**Коротко.** Деструктуризация раскладывает объект или массив по переменным. Три точки слева от `=` и в параметрах — rest, собирает остаток; справа и в вызове — spread, раскрывает. Копия через spread поверхностная.

**Развёрнуто.**

```js
const { name, age = 18, ...rest } = user
const [first, , third] = list
const next = { ...user, age: 31 } // при совпадении побеждает правое
```

- Вложенные объекты после `{ ...obj }` остаются общими; глубокую копию делает `structuredClone`.
- Значение по умолчанию срабатывает только на `undefined`, не на `null`.
- Деструктуризация `null` бросает ошибку — отсюда `function f({ a } = {})`.

### Что такое итераторы и генераторы?

**Коротко.** Итератор — объект с методом `next()`, который возвращает `{ value, done }`. Итерируемый объект отдаёт итератор через `Symbol.iterator` — на этом работают `for...of` и spread. Генератор `function*` — простой способ написать итератор: его выполнение приостанавливается на каждом `yield`.

**Развёрнуто.**

```js
function* ids() {
  let id = 1
  while (true) yield id++
}
const gen = ids()
gen.next().value // 1
gen.next().value // 2
```

- Значения вычисляются лениво, поэтому последовательность может быть бесконечной.
- Применения: обход дерева через `yield*`, постраничная загрузка асинхронным генератором и `for await`.
- Обычный объект не итерируем; его перебирают через `Object.entries`.

### Когда нужны Map и Set вместо объекта и массива?

**Коротко.** `Map` — словарь с ключами любого типа, порядком вставки и свойством `size`. `Set` — набор уникальных значений с быстрой проверкой `has`. Объект подходит для записи с известными полями; под словарь, который часто меняется, берут `Map`.

**Пример.**

```js
const visits = new Map()
const user = { id: 7 }
visits.set(user, 3) // ключом может быть сам объект
visits.set("гость", 1)
visits.get(user) // 3
visits.size // 2

// у объекта ключи-числа уходят вперёд, Map хранит порядок вставки
Object.keys({ b: 1, 2: 1, a: 1 }) // ["2", "b", "a"]
const order = [...new Map([["b", 1], [2, 1], ["a", 1]]).keys()]
// order: ["b", 2, "a"]

const seen = new Set([1, 2, 2, 3]) // дубликат отброшен
seen.size // 3
seen.has(2) // true: проверка за O(1), а не перебором
const letters = [...new Set("мама")] // ["м", "а"]
```

**Развёрнуто.**
- У объекта ключи — только строки и символы, а ключи, похожие на целые числа, идут первыми по возрастанию, не в порядке добавления.
- `[...new Set(arr)]` убирает дубликаты за один проход.
- `WeakMap` и `WeakSet` не удерживают ключи-объекты от сборки мусора — подходят для кэшей.

### Какие методы массива меняют исходный массив?

**Коротко.** Меняют: `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`. Возвращают новый: `map`, `filter`, `slice`, `concat`, `flat` и новые `toSorted`, `toReversed`, `toSpliced`, `with`.

**Развёрнуто.**
- `sort` без аргумента сравнивает элементы как строки: `[10, 9, 1].sort()` даёт `[1, 10, 9]`.
- Компаратор возвращает число — отрицательное, ноль или положительное: `(a, b) => a - b`. Булево значение из него — ошибка.
- Чтобы не испортить исходные данные, сортируют копию: `[...arr].sort(…)`.
- `includes` находит `NaN`, `indexOf` — нет.

### Что такое сложность алгоритма?

**Коротко.** Оценка того, как растёт время или память с ростом входных данных. Доступ по индексу и операции с `Map` и `Set` — O(1); один проход — O(n); вложенные циклы — O(n²); сортировка — O(n log n); двоичный поиск — O(log n).

**Пример.** Одна задача — есть ли в массиве повторы — двумя способами.

```js
// O(n²): includes сам перебирает массив — получается цикл в цикле
function hasDuplicateSlow(arr) {
  return arr.some((x, i) => arr.includes(x, i + 1))
}

// O(n): один проход, проверка в Set занимает O(1)
function hasDuplicate(arr) {
  const seen = new Set()
  for (const x of arr) {
    if (seen.has(x)) return true
    seen.add(x)
  }
  return false
}

// на 100 000 элементов: до 5 миллиардов сравнений против 100 тысяч
arr[5] // O(1): доступ по индексу
arr.find((x) => x > 5) // O(n): один проход
arr.toSorted() // O(n log n): сортировка
```

**Развёрнуто.**
- `includes` или `indexOf` внутри цикла — скрытый квадрат; заменяется на `Set` или `Map`.
- Константы и младшие слагаемые отбрасывают: два прохода подряд — всё равно O(n).
- Память тоже оценивают: дополнительный `Map` — это O(n).
- На интервью сложность своего решения лучше назвать самой, не дожидаясь вопроса.

### Чем debounce отличается от throttle?

**Коротко.** `debounce` откладывает вызов до паузы в событиях и срабатывает один раз после последнего. `throttle` пропускает не больше одного вызова за интервал. Поиск по вводу — `debounce`, прокрутка и изменение размера окна — `throttle`.

**Развёрнуто.**

```js
function debounce(fn, ms) {
  let timer
  return (...args) => {
    clearTimeout(timer)
    timer = setTimeout(() => fn(...args), ms)
  }
}
```

- `throttle` запоминает время последнего вызова и игнорирует события, пока интервал не прошёл.
- В компоненте отложенный вызов отменяют при размонтировании.

### Чем ES-модули отличаются от CommonJS?

**Коротко.** ES-модули — `import` и `export`; зависимости известны до выполнения, поэтому сборщик может выбросить неиспользуемый код. CommonJS — `require` и `module.exports`; модуль загружается во время выполнения. В браузере и современном коде — ES-модули.

**Развёрнуто.**
- Экспорт ES-модуля — живая связь со значением, в CommonJS — копия на момент `require`.
- `import()` возвращает промис и нужен для ленивой загрузки частей приложения.
- Модуль выполняется один раз, сколько бы раз его ни импортировали, и всегда в строгом режиме.

## 2. HTML и CSS

### Зачем нужна семантическая вёрстка?

**Коротко.** Тег выбирают по смыслу содержимого, а не по виду: `<nav>`, `<main>`, `<article>`, `<button>`. Это даёт доступность — скринридер строит по тегам карту страницы, поведение из коробки — кнопка сама ловит фокус и клавиши, и понятность для поисковиков.

**Развёрнуто.**
- Действие на странице — `<button>`, переход по адресу — `<a href>`.
- `<div>` с обработчиком клика не фокусируется, не нажимается с клавиатуры и не объявляется как кнопка.
- Заголовки идут по порядку без пропуска уровней; размер задают стилями.
- `<div>` и `<span>` — для обёрток без смысла.

### Из чего состоит правильная форма?

**Коротко.** `<form>` с полями, у каждого поля — `<label>`, атрибут `name` и подходящий `type`. Браузер умеет проверять значения сам: `required`, `pattern`, `min`, `max`, `type="email"`. Клиентская проверка — удобство, сервер проверяет заново.

**Развёрнуто.**
- Без `name` значение поля не отправится.
- `placeholder` не заменяет подпись: исчезает при вводе.
- Кнопка внутри формы по умолчанию отправляет её; остальным пишут `type="button"`.
- Состояние проверки доступно в CSS через `:valid` и `:invalid`, в JS — через `checkValidity()`.

### Что такое блочная модель и box-sizing?

**Коротко.** Каждый элемент — прямоугольник из содержимого, внутренних отступов, рамки и внешних отступов. По умолчанию `width` задаёт только содержимое; с `box-sizing: border-box` в ширину входят отступы и рамка, и считать размеры проще.

**Развёрнуто.**
- Вертикальные внешние отступы соседних блоков схлопываются: берётся больший, а не сумма.
- У строчных элементов `width`, `height` и вертикальные `margin` не работают; у `inline-block` — работают.
- `* { box-sizing: border-box }` — обычная первая строка стилей.

### Flexbox или Grid?

**Коротко.** Flexbox раскладывает элементы вдоль одной оси и хорош, когда размер диктует содержимое: меню, строка кнопок, центрирование. Grid работает сразу по двум осям и нужен, когда есть сетка: каркас страницы, каталог карточек. Обычно снаружи Grid, внутри ячеек Flexbox.

**Развёрнуто.**
- Flexbox: `justify-content` — вдоль главной оси, `align-items` — поперёк, `gap` — промежутки, `flex: 1` — делить место поровну.
- Grid: `grid-template-columns: repeat(auto-fill, minmax(220px, 1fr))` — число колонок меняется само, без медиазапросов.
- Длинное слово не даёт flex-элементу сжаться; лечится `min-width: 0`.

### Какие значения есть у position?

**Коротко.** `static` — обычный поток; `relative` — сдвиг от своего места, место сохраняется; `absolute` — вне потока, относительно ближайшего позиционированного предка; `fixed` — относительно окна; `sticky` — в потоке, пока не дойдёт до порога, дальше прилипает.

**Развёрнуто.**
- Чтобы `absolute` считался от родителя, родителю ставят `position: relative`.
- `sticky` не работает под предком с `overflow: hidden` и без заданного `top`.
- `z-index` действует только на позиционированные элементы и только внутри своего контекста наложения; контекст создают `position` с `z-index`, `opacity` меньше 1, `transform`.

### Как работают специфичность и каскад?

**Коротко.** Если на элемент претендуют несколько правил, побеждает более специфичный селектор: встроенный стиль сильнее идентификатора, идентификатор — класса, класс — тега. При равенстве выигрывает правило, записанное позже. `!important` перебивает всё это.

**Развёрнуто.**
- Считают тройкой: идентификаторы, затем классы с атрибутами и псевдоклассами, затем теги с псевдоэлементами. `#a .b p` — это 1-1-1.
- `:where()` имеет нулевую специфичность, `:is()` — специфичность самого тяжёлого аргумента.
- Часть свойств наследуется от родителя — цвет, шрифт; отступы и рамки — нет.

**Пример для `:is()` и `:where()`.** Разметка: `<div class="card"><p>текст</p></div>`.

```css
/* :is() весит как самый тяжёлый аргумент, то есть как #main: 1-0-1 */
:is(#main, .card) p { color: red; }

/* обычный класс и тег: 0-1-1 */
.card p { color: green; }

/* :where() не весит ничего, остаётся только p: 0-0-1 */
:where(#main, .card) p { color: blue; }
```

Текст будет красным: правило с `:is()` получило вес идентификатора, хотя элемент подошёл по классу. Без него победит зелёный, а синий проиграет любому правилу с классом — поэтому `:where()` берут для сбросов и стилей библиотек, которые должно быть легко перебить.

### Чем псевдокласс отличается от псевдоэлемента?

**Коротко.** Псевдокласс — состояние или положение существующего элемента, пишется с одним двоеточием: `:hover`, `:focus`, `:nth-child(2)`, `:not()`. Псевдоэлемент — часть элемента или вставка, которой нет в разметке, с двумя двоеточиями: `::before`, `::after`, `::placeholder`.

**Развёрнуто.**
- `::before` и `::after` не появятся без свойства `content`.
- `p:nth-child(2)` — «второй ребёнок, и он абзац»; `p:nth-of-type(2)` — «второй среди абзацев».
- `:focus-visible` показывает обводку только при навигации с клавиатуры.
- `:has()` выбирает по содержимому: `.card:has(img)`.

### Как отцентрировать элемент?

**Коротко.** Самый простой способ — на родителе `display: flex`, `justify-content: center`, `align-items: center`. В Grid — `display: grid` и `place-items: center`.

**Развёрнуто.**
- Блок с заданной шириной по горизонтали: `margin: 0 auto`.
- Текст и строчные элементы: `text-align: center`.
- Абсолютное позиционирование: `top: 50%`, `left: 50%`, `transform: translate(-50%, -50%)` — проценты в `translate` считаются от размера самого элемента.
- Современная короткая запись для `absolute`: `inset: 0` и `margin: auto` при заданных размерах.

### Чем отличаются display: none, visibility: hidden и opacity: 0?

**Коротко.** `display: none` убирает элемент из раскладки — места он не занимает. `visibility: hidden` оставляет место, но элемент не виден и не кликается. `opacity: 0` делает его прозрачным: место занято, клики и фокус работают.

**Развёрнуто.**
- Скринридер не читает первые два варианта, а прозрачный элемент — читает.
- `display` плавно анимировать нельзя, `opacity` — можно; поэтому появление делают парой `opacity` и `visibility`.
- Потомок может вернуть себе видимость через `visibility: visible`; с `display: none` у родителя — нет.

### Как сделать адаптивную вёрстку?

**Коротко.** Мета-тег `viewport`, резиновые размеры и медиазапросы там, где раскладка ломается. Пишут от узкого экрана к широкому: базовые стили — для телефона, расширения — через `min-width`.

**Развёрнуто.**
- Без `<meta name="viewport" content="width=device-width, initial-scale=1">` медиазапросы на телефоне не сработают.
- Точки перелома выбирают по содержимому, а не под модели устройств.
- Многое адаптируется без медиазапросов: `auto-fill` с `minmax` в Grid, `flex-wrap`, `clamp()` для размеров шрифта.
- Размеры шрифта — в `rem`: страница уважает настройки пользователя.
- `100vh` на телефоне выше экрана из-за адресной строки; есть `100dvh`.

### Как работают адаптивные картинки?

**Коротко.** В `srcset` перечисляют файлы разной ширины, в `sizes` — какой ширины картинка будет на экране; браузер сам выбирает подходящий файл с учётом плотности пикселей. `<picture>` нужен, когда меняется сам кадр или формат.

**Пример.**

```html
<img
  src="card-600.jpg"
  srcset="card-300.jpg 300w, card-600.jpg 600w, card-1200.jpg 1200w"
  sizes="(min-width: 768px) 50vw, 100vw"
  width="600" height="400"
  alt="Белые кроссовки, вид сбоку"
  loading="lazy"
/>

<picture>
  <source type="image/avif" srcset="hero.avif" />
  <source media="(max-width: 600px)" srcset="hero-tall.jpg" />
  <img src="hero-wide.jpg" alt="Летняя коллекция" />
</picture>
```

Как браузер выбирает файл для первой картинки: ширина на экране из `sizes`, умноженная на плотность пикселей. Ноутбук шириной 1200 с обычным экраном — половина окна, 600 пикселей, берётся `card-600.jpg`. Телефон шириной 300 с плотностью 2 — всё окно, 300 × 2 = 600, тот же файл.

**Развёрнуто.**
- `width` и `height` у `<img>` позволяют заранее занять место — страница не прыгает при загрузке.
- `alt` обязателен; у декоративных картинок он пустой.
- `loading="lazy"` откладывает загрузку картинок вне экрана.
- В `<picture>` браузер берёт первый подходящий `<source>`; `<img>` внутри обязателен как запасной вариант.

### Чем transition отличается от animation и что анимировать дёшево?

**Коротко.** `transition` плавно переводит свойство между двумя значениями, когда оно изменилось — по наведению или смене класса. `animation` с `@keyframes` — самостоятельный сценарий с промежуточными кадрами и повторами. Дёшево анимируются `transform` и `opacity`.

**Развёрнуто.**
- `transform` и `opacity` обрабатываются на этапе композитинга: без пересчёта геометрии и перерисовки, мимо главного потока.
- `width`, `height`, `top`, `left` заставляют пересчитывать раскладку на каждом кадре; вместо них — `translate` и `scale`.
- `transition` пишут на базовом состоянии, а не на `:hover`, иначе обратно элемент вернётся рывком.
- `prefers-reduced-motion` — медиазапрос, по которому анимации отключают.

- Ошибку CORS чинят на сервере или через прокси, а не на клиенте.

### Какие HTTP-методы и коды ответа нужно знать?

**Коротко.** GET читает, POST создаёт, PUT заменяет целиком, PATCH меняет часть, DELETE удаляет. Коды: 2xx — успех, 3xx — перенаправление, 4xx — ошибка клиента, 5xx — ошибка сервера.

**Развёрнуто.**
- Идемпотентны GET, PUT, DELETE: повтор запроса даёт то же состояние. POST — нет; PATCH — не гарантированно.
- 200, 201 «создано», 204 «без тела»; 301 и 302 — редиректы, 304 — «не изменилось»; 400 — плохой запрос, 401 — не авторизован, 403 — нет прав, 404 — не найдено; 500 — сбой сервера.
- 401 против 403: в первом случае сервер не знает, кто вы; во втором знает, но не пускает.

## 3. Vue, Pinia и Nuxt

### Как работает реактивность во Vue 3?

**Коротко.** На `Proxy`. Когда эффект — рендер компонента, `computed` или `watch` — читает реактивное свойство, Vue запоминает эту зависимость. При записи в свойство перезапускаются только те эффекты, которые его читали.

**Развёрнуто.**
- Чтение — track, запись — trigger. Рендер компонента тоже эффект, поэтому перерисовываются только зависящие компоненты.
- Обновления DOM копятся и применяются одной пачкой в следующем тике; дождаться — `await nextTick()`.
- Во Vue 2 реактивность была на `Object.defineProperty`: добавление свойства и запись по индексу массива не отслеживались.
- В отличие от React, код `setup` выполняется один раз, а не на каждый рендер.

### Чем ref отличается от reactive?

**Коротко.** `ref` оборачивает любое значение, в скрипте доступ через `.value`, в шаблоне — без него. `reactive` принимает только объекты и даёт доступ напрямую, но его нельзя заменить целиком и нельзя деструктурировать — связь теряется. По умолчанию берут `ref`.

**Развёрнуто.**
- `const { count } = state` для `reactive`-объекта даёт обычное число; спасает `toRefs(state)`.
- `state = reactive({ … })` рвёт связь с шаблоном; с `ref` замена `list.value = []` работает.
- Объект внутри `ref` тоже становится глубоко реактивным.
- Из composable удобнее возвращать объект из `ref` — его можно безопасно деструктурировать.

### Чем отличаются computed, watch и watchEffect?

**Коротко.** `computed` — значение, вычисляемое из других значений; кэшируется и пересчитывается только при изменении зависимостей. `watch` — побочный эффект в ответ на изменение конкретного источника, со старым и новым значением. `watchEffect` запускается сразу и сам собирает зависимости.

**Развёрнуто.**
- Внутри `computed` — никаких запросов и изменений других данных; метод в шаблоне, в отличие от него, выполняется на каждом рендере.
- Источник для `watch` — `ref`, реактивный объект или геттер: `watch(() => props.id, …)`. Передать `props.id` напрямую — ошибка.
- `watch` не срабатывает при создании без `immediate: true`.
- `watchEffect` отслеживает только то, что прочитано до первого `await`.

### Какие хуки жизненного цикла есть во Vue 3?

**Коротко.** Код `setup` выполняется один раз при создании, DOM ещё нет. Дальше `onBeforeMount`, `onMounted` — DOM вставлен; `onBeforeUpdate` и `onUpdated` — при перерисовке; `onBeforeUnmount` и `onUnmounted` — при удалении.

**Развёрнуто.**
- Работа с DOM, сторонние библиотеки, подписки на события окна — в `onMounted`; отписка — в `onBeforeUnmount`.
- `onMounted` ребёнка срабатывает раньше родительского.
- При серверном рендеринге `onMounted` не вызывается; данные для первой отрисовки грузят в `setup`, в Nuxt — через `useFetch`.
- `onErrorCaptured` ловит ошибки потомков.

### Чем v-if отличается от v-show и зачем key в v-for?

**Коротко.** `v-if` создаёт и удаляет узел, `v-show` переключает `display`. Первый дешевле при старте, второй — при частом переключении. `key` в `v-for` позволяет Vue сопоставить элементы списка между перерисовками, чтобы переиспользовать узлы и не перепутать их состояние.

**Развёрнуто.**
- Индекс массива в роли `key` ломается при вставке, удалении и сортировке: состояние строк съезжает на соседние.
- `v-if` и `v-for` на одном элементе не ставят: у `v-if` приоритет выше, и переменной цикла он не видит. Список фильтруют в `computed` или выносят цикл на `<template>`.

### Как компоненты общаются между собой?

**Коротко.** Данные вниз — через props, события вверх — через `emit`. `v-model` — их пара для двусторонней связи. Разметку передают слотами. Сквозь несколько уровней — `provide` и `inject`. Общее состояние приложения — в Pinia.

**Развёрнуто.**
- Props только для чтения: менять проп в ребёнке нельзя, нужно событие.
- Слот со своими данными (scoped slot) отдаёт значения из ребёнка в разметку родителя.
- `provide`/`inject` удобны для темы, локали, контекста формы; связь становится неявной.
- Шины событий `$on`/`$off` во Vue 3 нет.

### Как работает v-model на компоненте?

**Коротко.** `v-model` — сокращение для пары «привязать значение и слушать событие». На компоненте это проп `modelValue` и событие `update:modelValue`. С версии 3.4 их объявляет макрос `defineModel()`, который возвращает `ref`.

**Развёрнуто.**
- На нативном поле `v-model` разворачивается в `:value` и `@input`; для чекбокса — в `checked` и `change`.
- Именованных связей может быть несколько: `v-model:title` — проп `title` и событие `update:title`.
- Модификаторы: `.lazy`, `.number`, `.trim`.
- Во Vue 2 это были проп `value` и событие `input`, плюс `.sync`.

### Composition API или Options API?

**Коротко.** В Options API компонент — объект с опциями `data`, `computed`, `methods`, и логика одной задачи размазана по ним. В Composition API логику пишут функциями в `setup` и группируют по смыслу, а общее выносят в composables. Оба стиля поддерживаются; новый код пишут на Composition API.

**Развёрнуто.**
- Composable — функция `useSomething`, использующая `ref`, `computed`, `watch`; аналог кастомного хука React.
- Вместо миксинов: нет конфликтов имён, источник каждой функции виден по импорту.
- Типы TypeScript выводятся естественно: это обычные переменные и функции, без `this`.
- `<script setup>` — краткая запись: всё, что объявлено наверху, доступно в шаблоне.

### Что такое nextTick?

**Коротко.** Vue не обновляет DOM сразу после изменения состояния, а копит изменения и применяет их одной пачкой. `nextTick` возвращает промис, который выполнится после этого обновления, — так можно прочитать уже обновлённый DOM.

**Развёрнуто.**
- Типичный случай: показали поле ввода и хотят поставить в него фокус — `await nextTick()`, затем `input.value.focus()`.
- Несколько изменений подряд дадут одну перерисовку.

### Что такое Pinia и чем она отличается от Vuex?

**Коротко.** Pinia — официальный стор для Vue 3. Стор объявляют через `defineStore`: состояние, геттеры — те же `computed` — и действия, в том числе асинхронные. В отличие от Vuex, мутаций нет: состояние меняют напрямую или в действии; нет вложенных модулей, типы выводятся сами.

**Развёрнуто.**
- Два синтаксиса: объект с `state`, `getters`, `actions` или функция, где `ref` — состояние, `computed` — геттер, функция — действие.
- Стор — реактивный объект: деструктурировать его нужно через `storeToRefs`, действия — напрямую.
- `$patch` меняет несколько полей разом, `$reset` возвращает начальное состояние — только в объектном синтаксисе.
- В стор кладут общее для приложения: пользователя, корзину, настройки. Локальное состояние остаётся в компоненте.

### Как устроены формы и валидация во Vue?

**Коротко.** Поля связывают с состоянием через `v-model`, отправку перехватывают `@submit.prevent`. Простую валидацию пишут сами: ошибки — `computed` от значений формы. Для больших форм берут VeeValidate со схемой Zod или Yup либо Vuelidate.

**Развёрнуто.**
- Ошибки — производные данные; хранить их отдельным состоянием не нужно.
- Ошибку показывают после ухода с поля или попытки отправки, а не на первый символ.
- Кнопку блокируют на время запроса — защита от двойной отправки.
- Ошибки сервера раскладывают по полям тем же механизмом; клиентская проверка сервер не заменяет.

### Что такое Nuxt и зачем он нужен?

**Коротко.** Фреймворк над Vue: файловая маршрутизация, серверный рендеринг из коробки, автоимпорты компонентов и функций, собственный сервер и готовые средства загрузки данных. Это то же, что Next для React.

**Развёрнуто.**
- Режимы: универсальный рендеринг по умолчанию, только клиент (`ssr: false`), статическая генерация, гибрид по маршрутам через `routeRules`.
- Соглашения о папках: `pages/` — маршруты, `components/` и `composables/` — автоимпорт, `layouts/`, `middleware/`, `server/api/`.
- Серверный рендеринг нужен ради быстрого первого экрана и поисковиков — для каталога и карточки товара это критично.

### Что такое SSR, гидратация и hydration mismatch?

**Коротко.** При серверном рендеринге сервер отдаёт готовый HTML — страница видна сразу. Затем на клиенте Vue «оживляет» эту разметку, навешивая обработчики, — это гидратация. Если разметка клиента не совпала с серверной, возникает расхождение: предупреждение и перерисовка куска страницы.

**Развёрнуто.**
- Код `setup` выполняется дважды — на сервере и в браузере.
- `window`, `document`, `localStorage` на сервере нет: их используют в `onMounted` или в `<ClientOnly>`.
- Причины расхождения: текущее время, случайные числа, ветвление по данным браузера.
- Общее состояние в переменной модуля на сервере делят все посетители; нужны `useState` или Pinia.

### Как устроена маршрутизация в Nuxt?

**Коротко.** Маршруты строятся из файлов в `pages/`. Квадратные скобки — динамический сегмент: `pages/products/[id].vue` — это `/products/:id`, параметр читают через `useRoute().params.id`. Переходы — `<NuxtLink>` и `navigateTo`, проверки перед входом — route middleware.

**Развёрнуто.**
- `[...slug].vue` ловит хвост пути любой длины; `[[lang]]` — необязательный сегмент.
- Параметры всегда строки.
- Вложенные маршруты: файл-родитель с `<NuxtPage />` и одноимённая папка.
- Middleware возвращает `navigateTo(…)` для редиректа или ничего, чтобы пропустить; суффикс `.global` — для всех маршрутов.
- Обычный `<a href>` перезагрузит приложение целиком.

### Чем отличаются $fetch, useFetch и useAsyncData?

**Коротко.** `$fetch` — функция запроса, для действий по событию: отправить форму. `useFetch` и `useAsyncData` — для данных, нужных при отрисовке: запрос выполняется на сервере, результат кладётся в HTML и на клиенте повторно не запрашивается. `useFetch` — краткая запись `useAsyncData` плюс `$fetch`.

**Развёрнуто.**
- Голый `$fetch` в `setup` страницы уйдёт дважды: на сервере и при гидратации.
- Возвращают `data`, `status`, `error`, `refresh`; `data` — это `ref`, до загрузки он пуст.
- Чтобы запрос повторялся при смене параметра, адрес передают геттером: `useFetch(() => '/api/products/' + id.value)`.
- `lazy: true` не блокирует переход: страница открывается сразу с состоянием загрузки.
- `asyncData`, который до сих пор встречается в списках тем, — название метода из Nuxt 2.

### Vue и React: в чём главные различия?

**Коротко.** В React компонент — функция, которая выполняется заново при каждом изменении состояния, а лишнюю работу отсекают `memo`, `useMemo`, `useCallback`. Во Vue `setup` выполняется один раз, а реактивность сама знает, что от чего зависит, и обновляет точечно.

**Развёрнуто.**
- Состояние: в React неизменяемое и меняется сеттером; во Vue значение мутируют напрямую.
- Зависимости: в React их перечисляют массивом вручную; во Vue они собираются по фактическим чтениям.
- Разметка: JSX — это JavaScript; шаблон Vue — HTML с директивами, который компилятор заранее оптимизирует.
- Экосистема: React — библиотека с выбором решений; у Vue роутер и стор официальные.
- Хороший финал ответа: «подходы разные, задачи одни; после трёх лет на Vue и двух на React я вижу, что переносится понимание, а не синтаксис».

### Что изменилось между Vue 2 и Vue 3?

**Коротко.** Реактивность переехала с `Object.defineProperty` на `Proxy` и стала отслеживать всё; появился Composition API и `<script setup>`; Vuex сменила Pinia. Плюс фрагменты — несколько корневых элементов, `Teleport`, лучшая поддержка TypeScript.

**Развёрнуто.**
- `v-model` на компоненте: `value` и `input` стали `modelValue` и `update:modelValue`, `.sync` убран.
- Приоритет `v-if` и `v-for` поменялся местами.
- `new Vue()` заменён на `createApp()`; убраны фильтры и шина событий.
- В Nuxt: `asyncData` стал `useAsyncData`, файл `_id.vue` — `[id].vue`.

## 4. Инструменты

### Чем merge отличается от rebase?

**Коротко.** `merge` соединяет ветки коммитом слияния и сохраняет историю как была. `rebase` переносит твои коммиты поверх свежей ветки — история получается прямой, но коммиты создаются заново. Общую ветку перебазировать нельзя: у коллег история разойдётся.

**Развёрнуто.**
- Свою ветку перед запросом на слияние перебазировать нормально; после этого нужен `git push --force-with-lease`.
- `git fetch` только скачивает изменения; `git pull` — это `fetch` плюс слияние.
- Конфликт: правят файлы между маркерами, затем `git add` и `git rebase --continue` или коммит.

### Как отменить изменения в Git?

**Коротко.** Опубликованный коммит отменяют через `git revert` — он создаёт новый коммит с обратными изменениями. Локальный — через `git reset`, он переписывает историю. Правки в файле возвращает `git restore`.

**Развёрнуто.**
- `reset --soft` оставляет изменения в индексе, `--mixed` — в файлах, `--hard` стирает и их.
- `git commit --amend` поправляет последний коммит.
- `git stash` прячет незаконченные правки; `git cherry-pick` переносит один коммит в другую ветку.
- `git reflog` возвращает коммиты, потерянные после `reset --hard`.

### Что делает сборщик?

**Коротко.** Собирает модули и их зависимости в файлы для браузера: объединяет, преобразует TypeScript, шаблоны и стили, сжимает, выбрасывает неиспользуемый код и делит результат на части для ленивой загрузки.

**Развёрнуто.**
- Tree shaking работает на ES-модулях: неиспользуемые экспорты в сборку не попадают.
- Code splitting: `import()` выносит страницу или тяжёлый компонент в отдельный файл.
- Имена файлов содержат хеш содержимого, поэтому их можно кэшировать надолго.
- Vite при разработке отдаёт модули браузеру как есть и потому стартует мгновенно; для продакшена собирает бандл. Webpack всегда собирает бандл целиком.

### Что такое транспиляция и полифилы?

**Коротко.** Транспиляция переписывает новый синтаксис в понятный старым браузерам — этим занимаются Babel, esbuild, компилятор TypeScript. Полифил добавляет отсутствующую функцию или метод. Синтаксис транспилируют, возможности среды — полифилят.

**Развёрнуто.**
- Список поддерживаемых браузеров задают в `browserslist`; от него зависит, что преобразовывать.
- Стрелочную функцию можно переписать; `Promise` или `fetch` переписать нельзя — их добавляют полифилом.
- TypeScript при сборке просто стирает типы; проверку типов запускают отдельно.

### Что такое CI/CD?

**Коротко.** CI — на каждое изменение автоматически запускаются сборка и проверки, чтобы поломка находилась сразу. CD — проверенная сборка автоматически готовится к выкладке и раскатывается по окружениям.

**Развёрнуто.**
- Типичный конвейер фронтенда: установка зависимостей, линтер и проверка типов, модульные тесты, сборка, сквозные тесты, выкладка.
- Быстрые проверки идут первыми; упавшая стадия блокирует слияние.
- На конвейере ставят зависимости через `npm ci` — строго по lock-файлу.
- Секреты хранят в настройках CI; всё, что попало в клиентский бандл, секретом не является.

### Зачем нужен package-lock.json и что такое semver?

**Коротко.** `package.json` описывает зависимости диапазонами версий, а lock-файл фиксирует точные версии всего дерева — чтобы у всех и на сервере ставилось одно и то же. Semver — схема версий «мажорная.минорная.патч»: ломающие изменения, новые возможности, исправления.

**Развёрнуто.**
- `^1.2.3` разрешает обновления в пределах мажорной версии, `~1.2.3` — только патчи.
- `dependencies` нужны приложению в работе, `devDependencies` — только при разработке и сборке.
- Lock-файл хранят в репозитории.

## 5. Лайвкодинг: что могут дать

### Мой прогноз

Реальных задач здесь нет — это предположение, построенное на двух фактах. Первый: на странице в списке тем стоит «простейшие задачи на массивы и строки (например, сортировка, поиск)». Второй: скрининг длится 30–40 минут, и на код в нём остаётся 10–15.

| Вероятность | Что дадут |
| --- | --- |
| высокая | «Что выведет этот код?» — порядок вывода с `setTimeout` и промисами, замыкание в цикле, потерянный `this` |
| высокая | одна короткая функция на строку или массив |
| средняя | небольшая утилита: `debounce`, свой `map` или `filter`, каррирование |
| ниже | маленький кусок на Vue: composable или компонент со списком |

Самая вероятная пара — «что выведет код» про event loop и одна функция на строку или массив.

### «Что выведет код»: порядок выполнения

```js
console.log('1')
setTimeout(() => console.log('2'), 0)
Promise.resolve().then(() => console.log('3'))
;(async () => {
  console.log('4')
  await null
  console.log('5')
})()
console.log('6')
```

Ответ: `1 4 6 3 5 2`.

Как рассуждать вслух: сначала весь синхронный код — `1`, тело async-функции до первого `await` (`4`), затем `6`. Потом микрозадачи в порядке постановки: `then` (`3`), продолжение после `await` (`5`). И только потом макрозадача — таймер (`2`).

### «Что выведет код»: замыкание в цикле

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0)
}
```

Ответ: `3 3 3`. Переменная `var` одна на всю функцию; к моменту срабатывания таймеров цикл закончился, и `i` равно 3.

Как исправить: заменить `var` на `let` — у каждой итерации будет своя переменная, выведется `0 1 2`. Вариант до `let` — обернуть в функцию, которая принимает `i` аргументом.

### «Что выведет код»: потерянный this

```js
const user = {
  name: 'Аня',
  hi() { console.log(this.name) },
  bye: () => console.log(this.name),
}
user.hi()
const f = user.hi
f()
user.bye()
```

Ответ: `Аня`, затем ошибка или `undefined`, затем `undefined`.

Как рассуждать: `user.hi()` — вызов метода, `this` равен `user`. `f()` — обычный вызов: в строгом режиме и в модулях `this` равен `undefined`, обращение к `.name` бросит ошибку; в нестрогом выведется `undefined`. У стрелочной `bye` своего `this` нет — берётся внешний, а не `user`.

### «Что выведет код»: ссылки и копии

```js
const a = { name: 'Аня', tags: ['js'] }
const b = { ...a }
b.name = 'Оля'
b.tags.push('vue')
console.log(a.name, a.tags)
```

Ответ: `Аня ['js', 'vue']`. Spread копирует только верхний уровень: `name` у копии своё, а массив `tags` общий.

Рядом спрашивают: `[10, 9, 1].sort()` — `[1, 10, 9]`, сортировка по умолчанию строковая; `typeof null` — `'object'`; `0.1 + 0.2 === 0.3` — `false`.

### Задачи на строки

Что дают чаще всего: палиндром, анаграммы, самый частый символ, перевернуть слова, сжать строку (`'aaabbc'` → `'a3b2c'`), проверить скобки.

Проверка скобок — хороший пример, её стоит уметь написать:

```js
function isBalanced(str) {
  const pairs = { ')': '(', ']': '[', '}': '{' }
  const stack = []
  for (const ch of str) {
    if ('([{'.includes(ch)) stack.push(ch)
    else if (pairs[ch]) {
      if (stack.pop() !== pairs[ch]) return false
    }
  }
  return stack.length === 0
}
```

Идея: открывающую скобку кладём в стек, на закрывающей снимаем верхнюю и сверяем пару. В конце стек должен быть пуст. Сложность O(n).

### Задачи на массивы

Что дают чаще всего: убрать дубликаты, пересечение двух массивов, сгруппировать по ключу, сумма двух, развернуть вложенный массив, отсортировать объекты по полю, разбить на части заданного размера.

Сортировка по двум полям — место, где легко ошибиться:

```js
const sorted = [...users].sort(
  (a, b) => b.rank - a.rank || a.name.localeCompare(b.name, 'ru'),
)
```

Что произнести: сортирую копию, чтобы не менять исходный массив; компаратор возвращает число, а не булево значение; при равном `rank` разность даёт 0, и срабатывает второе сравнение — по имени.

Пересечение двух массивов: `const set = new Set(b); return a.filter((x) => set.has(x))` — O(n + m) вместо квадрата с `includes`.

### Утилиты на JavaScript

Что могут попросить: `debounce`, `throttle`, свой `map`, `filter` или `reduce`, мемоизацию, каррирование, свой `Promise.all`.

Свой `map` — самый короткий пример:

```js
function map(arr, fn) {
  const out = []
  for (let i = 0; i < arr.length; i++) out.push(fn(arr[i], i, arr))
  return out
}
```

Каррирование `sum(1)(2)(3)`:

```js
const sum = (a) => (b) => (c) => a + b + c
```

Мемоизация: `Map` в замыкании, ключ — аргумент, значение — результат; при повторном вызове с тем же аргументом возвращается сохранённое.

### Если попросят написать на Vue

Вероятные задания: счётчик, список с фильтром и добавлением, поле с `v-model` на своём компоненте, загрузка данных с состояниями «грузится / ошибка / готово».

Каркас, который должен писаться без раздумий:

```vue
<script setup>
const items = ref([])
const query = ref('')
const visible = computed(() => {
  const q = query.value.toLowerCase()
  return items.value.filter((i) => i.title.toLowerCase().includes(q))
})
</script>

<template>
  <input v-model="query" placeholder="Поиск" />
  <ul>
    <li v-for="item in visible" :key="item.id">{{ item.title }}</li>
  </ul>
</template>
```

Что проговорить: производный список — `computed`, а не отдельное состояние; `key` — идентификатор, не индекс; в скрипте `.value`, в шаблоне без него.

### Как вести себя на лайвкодинге

1. **Уточни условие до первой строки.** Что на входе, что с пустым значением, важен ли регистр, можно ли менять исходный массив.
2. **Скажи план вслух в двух предложениях** и только потом пиши.
3. **Сначала простое рабочее решение,** потом улучшение. Квадратичное, но верное лучше недописанного оптимального.
4. **Не молчи.** Интервьюер оценивает ход мысли; застряла — скажи, на чём именно.
5. **Проверь на примере руками:** обычный случай, пустой вход, один элемент.
6. **Прочитай, что код вывел на самом деле,** а не что должен был. Ошибку читай целиком, до конца строки.
7. **Назови сложность** и что бы изменила при больших данных.

Не помнишь название метода — скажи об этом и опиши, что он делает. Это нормально и не снижает оценку так, как молчание.
