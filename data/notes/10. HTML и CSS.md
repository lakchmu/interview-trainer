## 1. HTML: семантическая разметка, формы и мультимедиа

> [!tip]+ Коротко (что сказать вслух):
> Семантическая разметка — это выбор тега по смыслу содержимого, а не по внешнему виду: `<nav>` для навигации, `<button>` для действия, `<h1>`–`<h6>` для структуры. От неё зависят доступность (скринридер строит по тегам карту страницы), поисковая выдача и поведение «из коробки»: кнопка сама фокусируется и нажимается с клавиатуры, `<div>` — нет. Форма — это `<form>` с полями, у каждого есть `<label>` и подходящий `type`; браузер умеет проверять значения сам. Картинки и видео описывают так, чтобы браузер заранее знал их размер и мог выбрать подходящий файл.

### Семантические теги и что они дают

| Тег | Смысл | Роль для скринридера |
| --- | --- | --- |
| `<header>` | шапка страницы или раздела | banner (на уровне страницы) |
| `<nav>` | блок навигации | navigation |
| `<main>` | основное содержимое, одно на страницу | main |
| `<article>` | самостоятельный материал: товар, пост, отзыв | article |
| `<section>` | тематический раздел с заголовком | region (если есть имя) |
| `<aside>` | побочное содержимое | complementary |
| `<footer>` | подвал страницы или раздела | contentinfo |
| `<button>` | действие | button |
| `<a href>` | переход | link |

Что получаешь бесплатно:

- **доступность**: по ориентирам и заголовкам пользователь скринридера прыгает по странице, не слушая её целиком;
- **поведение**: `<button>` получает фокус и срабатывает от Enter и пробела; у `<div onclick>` всё это пришлось бы дописывать;
- **поиск**: поисковик понимает, где основное содержимое и какая у него структура.

### div или семантический тег: как выбрать

| Вопрос | Если «да» |
| --- | --- |
| По клику происходит действие на странице? | `<button type="button">` |
| По клику происходит переход по адресу? | `<a href>` |
| Это самостоятельная единица, которую можно вынести отдельно? | `<article>` |
| Это раздел с собственным заголовком? | `<section>` |
| Это список однотипных элементов? | `<ul>` или `<ol>` |
| Это табличные данные? | `<table>` с `<th>` |
| Нужна только обёртка для стилей? | `<div>` или `<span>` |

Заголовки идут по порядку, без пропусков уровней: `<h1>` один на страницу, под ним `<h2>`, под ними `<h3>`. Размер шрифта задают стилями, а не выбором уровня.

### Форма: из чего состоит

```html
<form action="/api/login" method="post">
  <label for="email">Почта</label>
  <input id="email" name="email" type="email" autocomplete="email" required />

  <fieldset>
    <legend>Способ доставки</legend>
    <label><input type="radio" name="delivery" value="courier" checked /> Курьер</label>
    <label><input type="radio" name="delivery" value="pickup" /> Самовывоз</label>
  </fieldset>

  <button type="submit">Войти</button>
</form>
```

- `name` — под этим именем значение уйдёт на сервер. Поле без `name` не отправляется.
- `<label>` связан с полем через `for` и `id` либо просто оборачивает его. Клик по подписи ставит фокус в поле, скринридер читает подпись.
- `<fieldset>` с `<legend>` группирует связанные поля — обязательно для радиокнопок.
- Кнопка внутри формы по умолчанию имеет `type="submit"`. Кнопке, которая форму не отправляет, пишут `type="button"`.

### Типы полей и встроенная валидация

| `type` | Что даёт |
| --- | --- |
| `email`, `url`, `tel` | проверку формата и нужную клавиатуру на телефоне |
| `number`, `range` | числа, атрибуты `min`, `max`, `step` |
| `date`, `time`, `datetime-local` | нативный выбор даты и времени |
| `password` | скрытый ввод, работу с менеджером паролей |
| `checkbox`, `radio` | выбор; радиокнопки объединяются общим `name` |
| `file` | выбор файла, `accept` и `multiple` |
| `search` | поле поиска с кнопкой очистки |

| Атрибут проверки | Что проверяет |
| --- | --- |
| `required` | поле заполнено |
| `minlength`, `maxlength` | длину строки |
| `min`, `max`, `step` | диапазон числа или даты |
| `pattern` | соответствие регулярному выражению |

Состояние проверки доступно в CSS через `:valid`, `:invalid`, `:user-invalid` и в JS через `input.validity` и `form.checkValidity()`. Атрибут `novalidate` на форме отключает браузерные подсказки, если рисуете свои.

### Картинки: img, srcset и picture

```html
<img
  src="phone-800.jpg"
  srcset="phone-400.jpg 400w, phone-800.jpg 800w, phone-1600.jpg 1600w"
  sizes="(max-width: 600px) 100vw, 400px"
  width="800" height="600"
  alt="Смартфон в синем корпусе, вид сзади"
  loading="lazy" decoding="async"
/>
```

| Атрибут | Зачем |
| --- | --- |
| `alt` | текст для скринридера и на случай, если картинка не загрузилась; у декоративных — пустой `alt=""` |
| `width`, `height` | браузер заранее резервирует место — страница не прыгает (CLS) |
| `srcset` + `sizes` | браузер сам выбирает файл под ширину экрана и плотность пикселей |
| `loading="lazy"` | грузить, когда картинка приблизится к области видимости |

`<picture>` нужен, когда меняется не размер, а сама картинка или формат:

```html
<picture>
  <source type="image/avif" srcset="banner.avif" />
  <source media="(max-width: 600px)" srcset="banner-square.jpg" />
  <img src="banner-wide.jpg" alt="Распродажа: скидки до 50%" />
</picture>
```

### Видео и аудио

```html
<video controls preload="metadata" poster="preview.jpg" width="1280" height="720">
  <source src="review.webm" type="video/webm" />
  <source src="review.mp4" type="video/mp4" />
  <track kind="captions" src="review.ru.vtt" srclang="ru" label="Русский" default />
  Ваш браузер не поддерживает видео.
</video>
```

| Атрибут | Что делает |
| --- | --- |
| `controls` | показывает стандартные кнопки управления |
| `preload` | `none`, `metadata` или `auto` — сколько грузить заранее |
| `poster` | картинка до начала воспроизведения |
| `autoplay` | автозапуск; браузеры разрешают его только вместе с `muted` |
| `playsinline` | на iOS играть на месте, а не на весь экран |
| `loop`, `muted` | повтор и выключенный звук |

- Несколько `<source>` — браузер берёт первый формат, который умеет.
- `<track kind="captions">` — субтитры: это и доступность, и просмотр без звука.
- `<audio>` устроен так же, только без картинки.

> [!warning]- Подводные камни:
> - `<div>` с обработчиком клика вместо `<button>`: не фокусируется, не нажимается с клавиатуры, не объявляется скринридером как кнопка.
> - Поле без `<label>`. `placeholder` подписью не считается: исчезает при вводе и плохо читается.
> - Кнопка внутри формы без `type="button"` отправляет форму.
> - Картинка без `width` и `height` — страница прыгает во время загрузки.
> - Отсутствующий `alt` и пустой `alt=""` — разные вещи: без атрибута скринридер прочитает имя файла, с пустым — пропустит картинку.
> - Пропуск уровней заголовков ради размера шрифта.
> - `autoplay` без `muted` браузер заблокирует.

## 2. CSS: Flexbox, Grid, позиционирование, псевдоклассы и псевдоэлементы

> [!tip]+ Коротко (что сказать вслух):
> Flexbox раскладывает элементы вдоль одной оси и хорош, когда размер диктует содержимое: меню, строка кнопок, карточка с прижатым низом. Grid раскладывает по двум осям сразу и хорош, когда есть сетка: каркас страницы, каталог карточек. Позиционирование вынимает элемент из обычного потока или сдвигает его: `relative`, `absolute`, `fixed`, `sticky`. Псевдокласс — это состояние или положение существующего элемента (`:hover`, `:nth-child`), псевдоэлемент — часть элемента или сгенерированная вставка (`::before`, `::placeholder`).

### Flexbox: свойства контейнера и элемента

| На контейнере | Что задаёт |
| --- | --- |
| `display: flex` | включает раскладку |
| `flex-direction` | главную ось: `row` или `column` |
| `justify-content` | распределение вдоль главной оси |
| `align-items` | выравнивание поперёк оси |
| `flex-wrap` | перенос на новую строку |
| `gap` | промежутки между элементами |

| На элементе | Что задаёт |
| --- | --- |
| `flex-grow` | долю свободного места, которую заберёт элемент |
| `flex-shrink` | насколько охотно сжимается при нехватке места |
| `flex-basis` | исходный размер до распределения |
| `align-self` | своё выравнивание поперёк оси |
| `order` | визуальный порядок |

`flex: 1` — это `1 1 0`: элементы делят место поровну, не глядя на содержимое. `flex: auto` — это `1 1 auto`: сначала учитывается ширина содержимого, делится только остаток.

Частая беда: длинный текст не даёт элементу сжаться, потому что у flex-элемента `min-width: auto`. Лечится `min-width: 0`.

### Grid: основные приёмы

```css
.catalog {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(220px, 1fr));
  gap: 16px;
}

.page {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-areas:
    'header header'
    'aside  main';
}
.page > header { grid-area: header; }
```

| Понятие | Что это |
| --- | --- |
| `fr` | доля свободного места |
| `repeat(3, 1fr)` | три равные колонки |
| `minmax(220px, 1fr)` | не уже 220px, но растягиваться можно |
| `auto-fill` / `auto-fit` | столько колонок, сколько влезет; `auto-fit` схлопывает пустые |
| `grid-column: 1 / 3` | элемент занимает линии с первой по третью |
| `grid-template-areas` | раскладка по именованным областям |

Первое правило каталога из примера адаптивно без единого медиазапроса: число колонок меняется само.

### Flexbox или Grid

| | Flexbox | Grid |
| --- | --- | --- |
| Измерения | одно: строка **или** колонка | два: строки **и** колонки |
| Кто главный | содержимое: элементы сами берут размер | контейнер: сетка задана заранее |
| Выравнивание между строками | нет, каждая строка сама по себе | есть: ячейки стоят по общим линиям |
| Типичные задачи | меню, панель кнопок, центрирование, прижать низ карточки | каркас страницы, каталог, форма в две колонки |

Они не соперники: обычная страница — это Grid снаружи и Flexbox внутри ячеек.

### Позиционирование

| `position` | Остаётся в потоке | Относительно чего сдвигается |
| --- | --- | --- |
| `static` | да | не сдвигается, `top` и `left` не работают |
| `relative` | да, место сохраняется | относительно своего обычного положения |
| `absolute` | нет | относительно ближайшего предка с `position` не `static` |
| `fixed` | нет | относительно окна браузера |
| `sticky` | да | ведёт себя как `relative`, пока не дойдёт до порога, дальше прилипает |

- `absolute` ищет предка с позиционированием; не найдя, привязывается к корню документа. Поэтому родителю ставят `position: relative`.
- `fixed` привязывается не к окну, а к предку, если у того есть `transform`, `filter` или `perspective`.
- `sticky` не работает, если у предка `overflow: hidden` или `auto`, и если не задан порог (`top`, `bottom`).
- `z-index` действует только внутри своего контекста наложения: элемент с `z-index: 9999` не вылезет из родителя, у которого контекст ниже соседнего.

### Псевдоклассы

| Группа | Примеры | Когда срабатывает |
| --- | --- | --- |
| действия пользователя | `:hover`, `:active`, `:focus`, `:focus-visible`, `:focus-within` | наведение, нажатие, фокус |
| состояние формы | `:checked`, `:disabled`, `:required`, `:valid`, `:invalid`, `:placeholder-shown` | по состоянию поля |
| положение в дереве | `:first-child`, `:last-child`, `:nth-child(2n)`, `:only-child` | среди всех соседей |
| положение по типу | `:first-of-type`, `:nth-of-type(2)` | среди соседей того же тега |
| логические | `:not()`, `:is()`, `:where()`, `:has()` | по условию |

- `:focus-visible` показывает обводку только при навигации с клавиатуры — мышью она не мозолит глаза.
- `:nth-child(2)` считает всех соседей, `:nth-of-type(2)` — только того же тега. `p:nth-child(2)` означает «второй ребёнок, и он — `p`», а не «второй абзац».
- `:has()` — выбор по содержимому: `.card:has(img)` — карточка, внутри которой есть картинка.
- `:where()` имеет нулевую специфичность, `:is()` берёт специфичность самого тяжёлого аргумента.

### Псевдоэлементы

| Псевдоэлемент | Что это |
| --- | --- |
| `::before`, `::after` | сгенерированное содержимое в начале и в конце элемента |
| `::placeholder` | текст-подсказка в поле |
| `::selection` | выделенный фрагмент |
| `::first-line`, `::first-letter` | первая строка и первая буква |
| `::marker` | маркер элемента списка |
| `::backdrop` | подложка под `<dialog>` и полноэкранным элементом |

```css
.required::after {
  content: ' *';
  color: crimson;
}
```

- Без свойства `content` `::before` и `::after` не появятся вовсе; для чистой декорации пишут `content: ''`.
- У элементов без содержимого (`<img>`, `<input>`, `<br>`) `::before` и `::after` не работают.
- Текст из `content` плохо доступен: не выделяется, не всегда читается скринридером. Смысл туда не кладут.
- Пишут с двумя двоеточиями; одно — старая запись, оставшаяся ради совместимости.

> [!warning]- Подводные камни:
> - Flex-элемент не сжимается из-за длинного слова или вложенного `<pre>` — нужен `min-width: 0`.
> - `position: absolute` без позиционированного предка улетает к краю страницы.
> - `position: sticky` молча не работает под предком с `overflow`.
> - `z-index` без `position` (вне flex и grid) не действует; а с ним — только внутри своего контекста наложения.
> - Путать `:nth-child` и `:nth-of-type`.
> - Вешать интерактив на `:hover` без `:focus-visible`: с клавиатуры до него не добраться.
> - Класть значимый текст в `::before`.

## 3. Адаптивная вёрстка: Media Queries и адаптивные картинки

> [!tip]+ Коротко (что сказать вслух):
> Адаптивная вёрстка начинается с `<meta name="viewport">` и резиновых размеров, а медиазапросы меняют раскладку в точках, где она перестаёт работать. Пишут mobile-first: базовые стили — для узкого экрана, расширения — через `min-width`. Точки перелома выбирают по содержимому, а не по моделям устройств. Многое адаптируется и без медиазапросов: `auto-fill` с `minmax` в Grid, `flex-wrap`, функция `clamp()`. Картинки подбирают через `srcset` и `sizes`, чтобы телефон не качал файл для монитора; `<picture>` — когда меняется кадр или формат.

### С чего начинается адаптив

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

Без этой строки телефон рисует страницу на условном холсте шириной около 980px и уменьшает её — медиазапросы по ширине не срабатывают.

| Единица | От чего считается |
| --- | --- |
| `%` | от размера родителя |
| `rem` | от размера шрифта корневого элемента |
| `em` | от размера шрифта самого элемента |
| `vw`, `vh` | от ширины и высоты окна |
| `dvh` | от высоты окна с учётом выезжающих панелей мобильного браузера |
| `fr` | от свободного места в Grid |

Размеры шрифта и отступов задают в `rem`: тогда страница уважает размер шрифта, выбранный человеком в настройках браузера.

### Медиазапросы: синтаксис

```css
.catalog { grid-template-columns: 1fr; }          /* телефон — база */

@media (min-width: 768px) {
  .catalog { grid-template-columns: repeat(2, 1fr); }
}

@media (min-width: 1200px) {
  .catalog { grid-template-columns: repeat(4, 1fr); }
}
```

| Условие | Что проверяет |
| --- | --- |
| `min-width`, `max-width` | ширину окна |
| `width >= 768px` | то же, новая запись диапазонами |
| `orientation: portrait` | ориентацию |
| `hover: hover` | есть ли у устройства настоящее наведение |
| `pointer: coarse` | грубый указатель — палец |
| `prefers-color-scheme: dark` | тёмную тему системы |
| `prefers-reduced-motion: reduce` | просьбу убавить анимации |

Условия соединяют через `and`, перечисляют через запятую (это «или»), отрицают через `not`.

### Mobile-first и выбор точек перелома

| | Mobile-first | Desktop-first |
| --- | --- | --- |
| Базовые стили | для узкого экрана | для широкого |
| Медиазапросы | `min-width` — добавляют сложность | `max-width` — отменяют сложность |
| Что получает слабое устройство | минимум правил | все правила плюс их отмену |

- Узкая раскладка обычно проще: одна колонка, всё подряд. Усложнять проще, чем отменять.
- Точку перелома ставят там, где **ломается содержимое** — строка стала слишком длинной, карточки слишком узкими, — а не «под iPhone».
- Не перекрывайте диапазоны: `max-width: 768px` и `min-width: 768px` оба сработают ровно на 768px. Берут `767.98px` или запись диапазоном.

### Адаптив без медиазапросов

```css
.catalog {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(220px, 1fr)); /* колонок сколько влезет */
}

h1 { font-size: clamp(1.5rem, 1rem + 2.5vw, 3rem); } /* плавно между минимумом и максимумом */

.toolbar { display: flex; flex-wrap: wrap; gap: 8px; } /* кнопки сами переносятся */

.media { width: min(100%, 720px); aspect-ratio: 16 / 9; }
```

| Инструмент | Что делает |
| --- | --- |
| `minmax()` + `auto-fill` | число колонок зависит от ширины контейнера |
| `clamp(min, ideal, max)` | значение плавно меняется в заданных пределах |
| `min()`, `max()` | выбор меньшего или большего из значений |
| `flex-wrap` | перенос элементов на новую строку |
| `aspect-ratio` | пропорции блока без трюков с отступами |

### Контейнерные запросы

```css
.card-wrap { container-type: inline-size; }

@container (min-width: 400px) {
  .card { display: grid; grid-template-columns: 120px 1fr; }
}
```

Медиазапрос смотрит на окно, контейнерный — на ширину **родителя**. Карточка товара может стоять и в узкой боковой колонке, и в широкой ленте: раскладка зависит от места, которое ей дали, а не от экрана. Это и делает компонент по-настоящему переносимым.

### Адаптивные картинки: srcset и sizes

```html
<img
  src="card-600.jpg"
  srcset="card-300.jpg 300w, card-600.jpg 600w, card-1200.jpg 1200w"
  sizes="(min-width: 1200px) 25vw, (min-width: 768px) 50vw, 100vw"
  alt="Кроссовки белые, вид сбоку"
/>
```

Как браузер выбирает файл:

1. Из `sizes` узнаёт, какой ширины будет картинка на экране: здесь четверть окна на широком экране, половина на среднем, вся ширина на телефоне.
2. Умножает на плотность пикселей устройства.
3. Берёт из `srcset` ближайший достаточный файл.

| Запись в `srcset` | Когда использовать |
| --- | --- |
| `300w`, `600w` — дескриптор ширины | картинка резиновая; обязателен `sizes` |
| `1x`, `2x` — дескриптор плотности | картинка фиксированного размера: логотип, иконка |

`sizes` — это подсказка о ширине на экране, а не стиль: размер картинки она не задаёт.

### picture: другой кадр и другой формат

```html
<picture>
  <source type="image/avif" srcset="hero.avif" />
  <source type="image/webp" srcset="hero.webp" />
  <source media="(max-width: 600px)" srcset="hero-portrait.jpg" />
  <img src="hero-wide.jpg" alt="Летняя коллекция" width="1600" height="600" />
</picture>
```

| Задача | Чем решать |
| --- | --- |
| тот же кадр, разные размеры | `srcset` + `sizes` на `<img>` |
| разные кадры под разные экраны (art direction) | `<picture>` с `media` |
| современный формат с запасным вариантом | `<picture>` с `type` |

Браузер идёт по `<source>` сверху вниз и берёт первый подходящий. `<img>` внутри обязателен: это запасной вариант, и именно на нём живут `alt`, размеры и стили.

Фоновые картинки в CSS подбирают функцией `image-set()` или медиазапросами.

> [!warning]- Подводные камни:
> - Нет `<meta name="viewport">` — медиазапросы на телефоне не работают.
> - Перекрывающиеся диапазоны `max-width: 768px` и `min-width: 768px`.
> - `100vh` на мобильном: адресная строка съедает часть высоты. Нужен `100dvh`.
> - `srcset` с дескрипторами ширины без `sizes` — браузер считает, что картинка во всю ширину окна, и берёт слишком большой файл.
> - Точки перелома «под устройства» вместо точек, где ломается содержимое.
> - Скрыть блок через `display: none` на телефоне — не значит не загрузить его картинки и скрипты.
> - Эффекты по `:hover` на сенсорном экране залипают. Их оборачивают в `@media (hover: hover)`.

## 4. Анимации и переходы: transition, transform и CSS-анимации

> [!tip]+ Коротко (что сказать вслух):
> `transition` плавно переводит свойство из одного значения в другое, когда оно изменилось — по наведению, смене класса. `@keyframes` с `animation` описывает самостоятельную анимацию с промежуточными кадрами, повторами и запуском без повода. `transform` двигает, масштабирует и поворачивает элемент, не трогая раскладку соседей. Анимировать стоит `transform` и `opacity`: они обрабатываются на этапе композитинга, без пересчёта геометрии и перерисовки. И всегда уважать `prefers-reduced-motion`.

### transition: из чего состоит

```css
.button {
  background: #005bff;
  transition: background-color 0.2s ease-out, transform 0.2s ease-out;
}
.button:hover {
  background: #0041b8;
  transform: translateY(-1px);
}
```

| Свойство | Что задаёт |
| --- | --- |
| `transition-property` | какие свойства анимировать |
| `transition-duration` | длительность |
| `transition-timing-function` | кривую скорости: `ease`, `linear`, `ease-in-out`, `cubic-bezier(…)` |
| `transition-delay` | задержку перед стартом |

- Переход пишут на **базовом** состоянии, а не на `:hover` — иначе обратно элемент вернётся рывком.
- `transition: all` анимирует всё подряд, включая то, что не собирались. Перечисляйте свойства явно.
- Анимируется только то, у чего есть промежуточные значения. `display` и `height: auto` к таким не относятся.

### transform: функции

| Функция | Что делает |
| --- | --- |
| `translate(x, y)` | сдвигает |
| `scale(n)` | масштабирует |
| `rotate(45deg)` | поворачивает |
| `skew(10deg)` | наклоняет |
| `translate3d`, `rotateX`, `perspective` | то же в трёх измерениях |

- Элемент сдвигается только визуально: место в раскладке остаётся прежним, соседи не двигаются.
- Порядок функций важен: `translate(100px) rotate(45deg)` и `rotate(45deg) translate(100px)` дают разный результат.
- `transform-origin` задаёт точку, вокруг которой идёт поворот и масштаб; по умолчанию это центр.
- Есть отдельные свойства `translate`, `rotate`, `scale` — их можно анимировать независимо друг от друга.
- Проценты в `translate` считаются от размера самого элемента. Отсюда классическое центрирование: `top: 50%; left: 50%; transform: translate(-50%, -50%)`.

### @keyframes и animation

```css
@keyframes pulse {
  0%, 100% { transform: scale(1); opacity: 1; }
  50% { transform: scale(1.08); opacity: 0.7; }
}

.badge {
  animation: pulse 1.2s ease-in-out infinite;
}
```

| Свойство | Что задаёт |
| --- | --- |
| `animation-name` | имя набора кадров |
| `animation-duration` | длительность одного цикла |
| `animation-timing-function` | кривую скорости |
| `animation-delay` | задержку |
| `animation-iteration-count` | число повторов или `infinite` |
| `animation-direction` | `normal`, `reverse`, `alternate` |
| `animation-fill-mode` | что показывать до и после: `forwards` оставляет последний кадр |
| `animation-play-state` | `running` или `paused` |

### transition или animation

| | `transition` | `animation` |
| --- | --- | --- |
| Что нужно для старта | изменение значения: класс, `:hover` | ничего, стартует сама |
| Кадры | начало и конец | сколько угодно промежуточных |
| Повторы | нет | есть, вплоть до бесконечных |
| Обратный ход | сам, при возврате значения | задаётся отдельно |
| Типичные задачи | наведение, раскрытие, смена темы | индикатор загрузки, привлечение внимания, появление |

Правило выбора: есть два состояния и переход между ними — `transition`; нужен сценарий — `animation`.

### Что анимировать дёшево

| Свойства | Какие стадии запускает | Цена |
| --- | --- | --- |
| `transform`, `opacity` | только композитинг | минимальная, идёт мимо главного потока |
| `color`, `background-color`, `box-shadow` | перерисовка | средняя |
| `width`, `height`, `top`, `left`, `margin` | пересчёт геометрии и перерисовка | высокая |

Вместо `left` двигают через `translate`, вместо `width` — через `scale`, появление делают через `opacity`.

`will-change: transform` заранее выносит элемент на отдельный слой. Ставят точечно и ненадолго: каждый слой занимает память. Подробно конвейер и слои разобраны в конспекте про браузер, раздел 5.

### Анимация появления и исчезновения

Сложность в том, что `display: none` переходов не знает: элемент исчезает мгновенно.

| Приём | Как работает |
| --- | --- |
| `opacity` + `visibility` | элемент остаётся в раскладке, но невидим и некликабелен |
| класс и событие `transitionend` | сначала анимируем, по окончании убираем из DOM |
| `<Transition>` во Vue | делает то же сам: вешает классы `v-enter-from`, `v-leave-to` и ждёт конец перехода |
| `@starting-style` и `transition-behavior: allow-discrete` | новый чисто CSS-способ анимировать вход и выход с `display` |

```css
.tooltip {
  opacity: 0;
  visibility: hidden;
  transition: opacity 0.15s, visibility 0.15s;
}
.tooltip.open {
  opacity: 1;
  visibility: visible;
}
```

### Доступность: prefers-reduced-motion

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

- У части людей движение на экране вызывает головокружение и тошноту. Настройка «уменьшить движение» есть во всех системах, медиазапрос её читает.
- Отключают прежде всего крупное: параллакс, перелёты, масштабирование. Смену прозрачности обычно можно оставить.
- Бесконечная анимация должна останавливаться или ставиться на паузу.
- Длительность интерфейсных переходов — 150–300 мс: короче незаметно, длиннее ощущается как задержка.

> [!warning]- Подводные камни:
> - Анимация `width`, `height`, `top`, `left` — пересчёт геометрии на каждом кадре.
> - `transition` на `:hover` вместо базового состояния — возврат рывком.
> - `transition: all` — случайно анимируется лишнее, страдает производительность.
> - Попытка анимировать `display` или `height: auto` обычным переходом.
> - `will-change` на всём подряд — память уходит на слои.
> - Забытый `animation-fill-mode: forwards`: после окончания элемент прыгает к исходному виду.
> - Анимации без `prefers-reduced-motion`.
